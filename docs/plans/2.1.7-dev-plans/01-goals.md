## 3. 目标

1. **看得懂**：新用户在无文档情况下，10 分钟内理解三个 CLI 入口（bash/claude/codex）、Provider 页结构、文件改动含义。
2. **等得明**：构建与 Docker 安装两个长等待场景全程有真实进度与阶段感，原始日志可查。
3. **管得清**：首页历史可清理、可展开、失效可识别；引导不挡路。
4. **性能底线**：大量产物场景产物面板不卡死不狂转；弱机轮询不整树闪烁。

## 5. 审阅补充：风险、边界与开放门

### 5.1 全局不变量

1. **不伪造事实**：无可靠进度源时不显示百分比；无 authoritative provenance 时不推断文件来源或重命名。
2. **不越过删除边界**：任何“彻底忘记”实现都只能操作 resolver 返回的 AISC data-root 资源；用户 workspace、workspace 内文件、非 AISC Docker 资源始终不可触碰。
3. **不解析人类文本做控制面**：winget 文本、普通 Docker 控制台文本只进入详细日志，不能成为状态机事实源。
4. **不复制状态链**：环境检测、Docker 唤醒、preflight/reconcile 复用既有 store/IPC；不得为“内嵌卡片”另建一套 readiness 判断。
5. **不记录敏感内容**：删除预览、日志、build events、教学练习记录不得包含 API key、完整配置、prompt 或终端 scrollback。

### 5.2 主要风险

| 风险 | 影响 | 缓解/门禁 |
|---|---|---|
| S2 删除目录成功但历史 CAS 失败，或反向发生 | 状态半完成、残留或误导 | 后端单命令、固定锁序、结构化逐项结果、幂等重试；禁止前端串两次 IPC |
| 路径已移动后重新 canonicalize 得到不同 hash | 删错/删不到 data-root | 优先使用历史/lease 已记录 workspace key；旧记录才用统一 hash fixture 回退 |
| Docker 安装超时后子进程仍存活 | UI 报超时但后台继续安装 | timeout 必须 kill + wait/reap，并回传 terminal result |
| Dockerfile 指令数与 BuildKit 输出不能一一映射 | 百分比失真 | 只有结构化事件可映射时显示 `%`；否则显示步骤 X/Y 或不确定进度 |
| `help` 覆盖 Bash builtin 或被 Claude/Codex TUI 吞掉 | 改变 shell 行为、教学入口失效 | S6 前 spike；保留 builtin 委托；非 Bash tab 使用 UI 入口或专用命令 |
| S5/S7 仅靠 watcher 推断事实 | 转圈未解、徽章误报 | 调查/数据源盘点先行；证据不足就降级，不猜测 |

### 5.3 开工前必须冻结的门

- **Gate-S2**（已关闭 2026-08-27，用户拍板）：host-bind toolchain 随 data-root 子树删除；named volume **保留 + 列项告警**——不自动删除，检测结果中列出并提示手动处理。见 decisions.md D12。
- **Gate-S4**：冻结 `aisc.build-events/v2` 与 Docker install progress event 字段、兼容策略和 fixture。
- **Gate-S5**：用户过目 `spike-artifact-flood.md` 后才允许提交修复。
- **Gate-S6**：完成 help 注入 spike，记录候选、兼容矩阵、选型和回滚方式。
- **Gate-S7**：列出现有新增/修改/删除/移动、Agent 归因各自的权威数据源；缺项即缩小验收，不伪造四分类。
