# AISC v2.1.4

> Codex 现在默认保持官方直连。AISC 仍会启动 cc-switch 并自动接管 Claude，但只有在你明确需要托管 Provider 时才启用 Codex 代理。

## 版本亮点

| 领域 | v2.1.4 的变化 | 用户收益 |
| --- | --- | --- |
| Codex 登录 | 默认不再执行 `cc-switch proxy -a codex enable` | 官方网页登录和本地 Codex 凭据不再被托管路由干扰 |
| cc-switch 管理 | 启动菜单新增 cc-switch TUI | 在容器入口直接管理 Provider、路由和 Skills |
| Skills 启动性能 | 默认使用 `AISC_SKILLS_SYNC=auto` | 内容未变化时跳过重复复制、数据库写入和全量同步 |
| 用户状态 | 不再强制重置 `enabled_claude` / `enabled_codex` | 手动停用的 skill 在容器重启后仍保持停用 |
| Windows 安全性 | 文件锁不可用时检查三处 Skills 目录并请求确认 | 默认保留宿主已有内容，避免静默覆盖 |

## Codex 官方登录与托管账号

新容器启动时：

- cc-switch daemon 仍会就绪，并保留 Codex Provider 的初始化能力。
- Claude 路由仍以 best-effort 方式自动启用。
- Codex 路由默认关闭，`codex` 直接使用官方登录或 Codex 自己的本地配置。

需要使用 cc-switch 托管的 Codex Provider 时，在容器内显式运行：

```bash
cc-switch proxy -a codex enable
```

需要恢复官方直连时运行：

```bash
cc-switch proxy -a codex disable
```

这避免了 cc-switch 托管状态被 Codex 界面误认为真实官方登录，也不再要求为了进入官方登录流程而先执行一次 `/logout`。

## cc-switch 与 Skills

- 容器交互菜单增加第 4 项 `cc-switch`，退出 TUI 后结束该前台会话。
- 镜像构建时生成内置 bundle 哈希；启动时同时检查哈希、SQLite 登记和已启用目标目录。
- `auto` 仅在首次安装、bundle 变化、登记缺失或目标缺失时同步。
- `always` 可强制重新同步，`off` 可完全关闭 AISC 的自动同步。
- 同步成功后才更新 `.cc-switch/.aisc-bundled-skills.sha256`；失败会在下次启动重试。

## Windows / Docker Desktop 保护

当绑定挂载不支持 `flock` 时，AISC 不再无条件复制：

1. `.cc-switch/skills`、`.claude/skills`、`.codex/skills` 全部不存在时，认领首次安装并继续。
2. 任一目录已经存在或仅部分存在时，交互环境显示 `[y/N]`。
3. 空输入和非交互环境默认跳过同步，保留宿主内容。
4. `AISC_SKILLS_SYNC=always` 也不会绕过该保护。
