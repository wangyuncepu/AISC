## 审阅后状态（2026-08-27）

> 本节记录审阅建议，尚未标注【用户】的条目不等同于用户最终拍板。

- **D3 审阅结论：接受默认交互，修订检查边界。** “失败内嵌启动卡片”符合现有 picker → preflight → summary 架构，优于重新弹整页向导。仅 workspace launch checks 后移；CLI negotiate 保留全局 gate，WebView2 不纳入卡片。失败卡必须支持返回 picker/重检/诊断，且不得自动安装 Docker。
- **D8 审阅结论：接受。** 不解析 winget 人类输出，使用后端心跳 + elapsed/deadline 是合理默认。补充硬约束：winget/bundled 两后端一致、operation id 防晚到覆盖、timeout/cancel 必须 kill+reap、安装与 engine-start 分阶段。
- **D9 审阅结论：接受“诚实进度”原则，但修订百分比算法。** Dockerfile 指令数只能作为候选总步数；只有结构化机器事件可可靠映射时才产生 `%`。拉取层字节是独立阶段进度，不能与指令步数合成一个整体百分比；其余场景显示 X/Y 或 indeterminate。
- **D10 审阅结论：继续开放，但缩小 spike。** PTY 首屏注入不能实现真实 shell 的后续 `help` 响应，只保留为静态卡方案。spike 比较“受控 Bash 启动文件 + builtin 委托”与“独立 `aisc-help` 命令/UI 教程入口”；不优先使用 PROMPT_COMMAND，不允许 Workbench 拦截普通终端输入。

- **D11 删除事务与身份**（审阅建议）：forget 以 workspace key + data-root resolver 为身份，不由前端拼路径；后端单命令结构化返回、幂等、fail-closed。路径失效的清记录仍是另一条非破坏操作。
- **D12 Toolchain 删除边界**（已关闭 2026-08-27）：host-bind toolchain 属于 workspace data 子树；Docker named volume **保留 + 列项告警**——本期「彻底忘记」绝不自动删除 named volume，检测到时在结构化结果中列出并提示手动处理（用户拍板，与 docker-resource-lifecycle 归属分类语义一致）。
- **D13 Build 日志边界**（审阅建议）：详细日志语义为“完整可访问”，不等于前端无界常驻内存。完整输出落 operation log；UI 渲染有界窗口/虚拟列表。
- **D14 文件徽章事实源**（审阅建议）：四分类与来源角标只有在权威数据存在时显示；不能为了视觉完整伪造 rename/delete/Agent 归因。
- **D15 互动练习成本边界**（审阅建议）：教程默认练习不联网、不计费；真实 Claude/Codex 命令需用户显式确认。
