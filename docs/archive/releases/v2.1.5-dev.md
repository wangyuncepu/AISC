# AISC v2.1.5-dev Preview

这是 v2.1.5 的预览版本，重点提升 cc-switch v5 兼容性、凭据安全、容器并发安全和发布产物可靠性。

## 主要变化

### cc-switch v5 Provider 预配置

容器首次启动时，会为 Claude 和 Codex 分别添加以下五个不含 API Key 的 Provider：

| Provider | ID | 默认模型 |
| --- | --- | --- |
| DeepSeek | `deepseek` | `deepseek-chat` |
| Codex Claude | `codex-claude` | `claude-opus-5` |
| 火山引擎 Ark | `volcengine-ark` | 由用户填写推理接入点 ID |
| 智谱 GLM | `zhipu` | `glm-4-plus` |
| Kimi | `kimi` | `moonshot-v1-128k` |

- Provider 数据使用 cc-switch v5 的 `app_type` 和 `settings_config` schema。
- Claude 与 Codex 使用独立版本标记，重复启动不会产生重复数据。
- Codex 配置使用 Responses API：`wire_api = "responses"`。
- 所有预置项默认 `is_current=0`，不会覆盖或自动切换用户现有 Provider。
- 插入在单一事务中完成；schema 不兼容或任意写入失败时会完整回滚。

可通过 `AISC_PRESET_PROVIDERS=auto|always|off` 控制预配置行为。

### Provider 凭据安全

宿主机命令不再通过命令行参数接收 API Key。运行：

```bash
aisc provider set-key --agent claude deepseek
```

AISC 会在目标容器内打开 cc-switch 的交互式 Provider 编辑器：

```bash
cc-switch -a claude provider edit deepseek
```

这样可以避免密钥出现在 shell history、进程参数和 AISC 事件输出中。

### Doctor 与自动修复

- `aisc doctor --format json` 始终输出纯 JSON，不再出现交互提示或额外文本。
- 只有明确检测到 Docker CLI 缺失时，交互式文本模式才会询问是否安装。
- macOS Homebrew 安装会实时显示输出，并在安装后将 Homebrew 路径加入当前进程的 `PATH`。

### 容器与代理可靠性

- 容器 registry 的读、改、写现在由同一个文件锁覆盖，避免并发更新丢失。
- GC 删除前会重新读取 registry，避免误删同名的新注册容器。
- Mihomo 会为原生 Clash YAML 注入以下本地直连规则，并放在已有规则之前：

```text
IP-CIDR,127.0.0.0/8,DIRECT
DOMAIN-KEYWORD,localhost,DIRECT
```

### Vendor 与发布产物

- Vendor 刷新和校验只处理 Git 跟踪文件，不再把 `.pyc` 等未跟踪产物纳入 checksum。
- 校验使用 Git index 处理 CRLF checkout，避免平台换行差异造成误报。
- Artifact staging 对未修改的跟踪容器文件使用 index 字节，保证发布内容与校验值一致。

## 升级说明

- 已有 Provider 不会被覆盖，现有凭据也不会被迁移或输出。
- 缺失的预置 Provider 会在首次启动时补齐；可设置 `AISC_PRESET_PROVIDERS=off` 禁用。
- 从源码安装时重新构建镜像，使容器脚本和 cc-switch `v5.9.0` 固定版本生效。
- 这是预览版本；升级前仍建议备份项目中的 `.cc-switch`、`.claude` 和 `.codex`。
