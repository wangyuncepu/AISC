# S5.3 生产发布前门禁

> 状态：不阻塞 CLI Demo；阻塞真实密钥迁移、S5.3 基线冻结与生产发布。
>
> Demo 约束：仅使用假密钥和临时目录，不执行 `config migrate` 或 `provider use`。

## 必须关闭

- [ ] Windows secure-store 消除父目录 reparse/junction 检查与最终路径操作之间的 TOCTOU 竞态。
- [ ] Windows 创建私密文件前验证目标目录 DACL：仅当前用户与 SYSTEM Full Control、DACL protected、无继承或 broad principal ALLOW ACE。
- [ ] 修正 Windows `APPDATA` / `LOCALAPPDATA` 路径校验：本阶段仅接受本地盘绝对路径；识别并拒绝相对路径、`C:relative`、root-relative、所有 UNC（包括完整 server + share）、device namespace 与 NT object namespace。UNC 支持推迟到具备 SMB 实机证据的后续阶段。
- [ ] 修正 macOS secrets 路径为 `~/Library/Application Support/aisc/secrets/`，保持 config/state/secrets 分离。
- [ ] 为以上路径与权限边界增加自动化测试，并在最终工作树上完成 Windows 实机回归。

## 冻结前评估

- [ ] 创建后安全验证失败时，对本次新建文件/目录进行安全回滚，避免目标路径被永久毒化。
- [ ] 修复 Windows SID/ACL 错误路径的资源释放。
- [ ] 完善 Windows leaf name 校验：拒绝非法字符，并识别带扩展名的保留设备名（如 `CON.txt`、`COM1.json`）。
- [ ] 清除 `tests/manual/__pycache__/` 等生成物，并将 S5.3 与 doctor/provider/run UX 拆为可独立回滚的提交。

## 已独立移出 S5.3 门禁

- `aisc run --non-interactive` 的 JSON/JSONL stdout 纯净性属于 CLI Demo 协议问题，应在 Demo 交付前修复。
- provider/profile 未知子命令的 JSON usage error 属于 CLI 协议一致性，应在 Demo 交付前验证。

## 生产解锁条件

只有在“必须关闭”全部完成，且 Windows 实机回归证据更新后，才允许：

1. 冻结 S5.3 secure-store 基线；
2. 让 S5.4 `config migrate` 依赖真实 secure-store；
3. 使用真实用户凭据演示或发布密钥迁移能力。
