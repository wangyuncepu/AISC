## Finding #1: `_O_CREAT_FILE` 缺少 `hasattr` 守卫 → 模块导入崩溃

**文件**：`src/aisc/adapters/secret_store.py:281`

**根因**：`O_NOFOLLOW`/`O_DIRECTORY`/`O_CLOEXEC` 是 POSIX-only 常量，Windows CPython 不存在。
模块级代码在第 268–279 行对 `O_NOFOLLOW`/`O_DIRECTORY`/`O_CLOEXEC` 做了 `hasattr` 守卫，
但第 281 行的 `_O_CREAT_FILE` 漏掉了守卫：

```python
# Line 268-279: GUARDED ✓
_O_RDONLY_DIR = _os.O_RDONLY
if hasattr(_os, "O_NOFOLLOW"):
    _O_RDONLY_DIR |= _os.O_NOFOLLOW
...
_O_RDWR_DIR = _os.O_RDWR
if hasattr(_os, "O_NOFOLLOW"):
    _O_RDWR_DIR |= _os.O_NOFOLLOW

# Line 281: UNGUARDED ✗
_O_CREAT_FILE = _os.O_CREAT | _os.O_EXCL | _os.O_WRONLY | _os.O_NOFOLLOW
```

**影响**：整个 `secret_store` 模块无法导入，所有 S5.3 相关测试 0 个执行。
Python 3.14 上同样崩溃（`O_NOFOLLOW` 已完全移除），但 Python 3.12 上同样不存在该常量。

**修复**：对 `_O_CREAT_FILE` 添加 `hasattr` 守卫，与 `_O_RDONLY_DIR`/`_O_RDWR_DIR` 保持一致。
**状态**：✅ 已修复

## Finding #2: POSIX 测试类缺少 `skipUnless(os.name != "nt")` 守卫

**文件**：`tests/unit/test_secret_store.py`

**根因**：`TestPosixDirFd`、`TestPosixCreatePrivateFile`、`TestPosixSecureDirectory` 三个测试类
没有平台守卫装饰器。在 Windows 上 `os.open("/")` 触发 `PermissionError`。
这些测试验证 POSIX dir_fd 路径，Windows 上走完全不同的 `_RealWinSecretBackend` 代码路径。

**影响**：27 个 ERROR（POSIX 测试 + Windows real tests）。POSIX 测试在 Windows 上无意义，
混淆测试结果。不阻塞核心功能验证。

**建议**：三个类各加 `@unittest.skipUnless(os.name != "nt", "POSIX only")`。
**状态**：✅ 已修复（非 S5.3 Windows 验证阻塞项）

## Finding #3: `_make_well_known_sid` 调用者传入多余 padding → `AllocateAndInitializeSid` 参数过多

**文件**：`src/aisc/adapters/secret_store.py:1283`

**根因**：`_make_well_known_sid(rid, *sub_auths)` 设计为 `rid` 是第一子权限，
`*sub_auths` 是额外子权限。函数内部自动 padding 到 8 个 `DWORD`。
但调用者传入 8 个 padding 值（`1, 0, 0, 0, 0, 0, 0, 0`），导致：

```python
sub_count = 1 + len(sub_auths)  # = 1 + 8 = 9  ❌ 应该是 1
args = [authority, c_byte(9), rid, 8×DWORD, pSid]  # 12 args, API 需 11
```

SYSTEM SID (S-1-5-18) 只需 1 个子权限（RID=18）。调用者多传了 8 个 padding 0。

**影响**：Windows real backend 完全不可用。`ensure_secure_directory` 和 `create_private_file`
在创建/验证目录第一步就崩溃。

**修复**：
```python
# Before (line 1283):
system_sid = self._make_well_known_sid(
    _SECURITY_LOCAL_SYSTEM_RID, 1, 0, 0, 0, 0, 0, 0, 0
)
# After:
system_sid = self._make_well_known_sid(_SECURITY_LOCAL_SYSTEM_RID)
```
**状态**：✅ 已修复

## Finding #4: `resolve_store_paths` 使用 `os.path.join` → 跨平台路径分隔符错误

**文件**：`src/aisc/adapters/secret_store.py:88-93`（Linux 分支）

**根因**：`resolve_store_paths` 号称 "pure function — no disk I/O"，但使用 `os.path.join`
拼接路径，`os.path.join` 使用宿主 OS 分隔符。Windows 上拼接 Linux 路径时产生 `\`：

```
os.path.join("/home/user", ".config") → "/home/user\\.config"
```

**影响**：5 个 `TestResolveStorePaths` Linux/darwin 测试 FAIL。不影响 Windows 平台路径解析。

**建议**：按 `platform_name` 使用 `posixpath.join` / `ntpath.join`。
**状态**：✅ 已修复（非 S5.3 Windows 验证阻塞项）

## Finding #5: `_is_forbidden_sid` — `memmove` 不接受 tuple 参数

**文件**：`src/aisc/adapters/secret_store.py:1621`

**根因**：Everyone SID 创建用 `ctypes.memmove(auth_world.Value, (0, 0, 0, 0, 0, 1), 6)`。
第二个参数是 Python tuple，`memmove` 需要 ctypes 数组/指针或 bytes-like object。
对比正确写法用 `_SECURITY_NT_AUTHORITY_VAL`（预定义的 `c_ubyte * 6` 数组）。

```python
# Line 1621 — BROKEN:
_ct.memmove(auth_world.Value, (0, 0, 0, 0, 0, 1), 6)

# Line 1633 — OK (uses pre-built ctypes array):
_ct.memmove(auth_nt.Value, _SECURITY_NT_AUTHORITY_VAL, 6)
```

**影响**：`_verify_dacl` → `_is_forbidden_sid` 崩溃，Windows real tests 全部 ERROR。

**修复**：用 `bytes([0, 0, 0, 0, 0, 1])` 替代 tuple。
**状态**：✅ 已修复

## Finding #6: `os.open_osfhandle` 不存在 → 应用 `msvcrt.open_osfhandle`

**文件**：`src/aisc/adapters/secret_store.py:1114`

**根因**：`_os.open_osfhandle(handle, fd_flags)` — `os` 模块无此函数。
正确 API 是 `msvcrt.open_osfhandle`（Windows 专属内置模块，将 Win32 HANDLE 转为 CRT fd）。

**影响**：`create_private_file` Windows 路径 100% 崩溃。

**修复**：用 `msvcrt.open_osfhandle` 替代。
**状态**：✅ 已修复

## Finding #7: Verifier `_dacl_info` SID 检测用字符串 "SYSTEM" 匹配 → 误判 FAIL

**文件**：`tests/manual/verify_s5_3_windows.py:332`

**根因**：`ConvertSidToStringSidW` 返回 `S-1-5-18`（SYSTEM SID 的 SDDL 格式），不含 "SYSTEM" 字样。
Verifier 用 `"SYSTEM" in sid_str.upper()` 检测 SYSTEM ACE，永远为 False。

```python
# BROKEN: S-1-5-18 不含 "SYSTEM"
if "SYSTEM" in sid_str.upper():
    has_system = True

# FIX: 直接比较标准 SDDL 字符串
if sid_str == "S-1-5-18":
    has_system = True
```

**影响**：即使 DACL 完全正确（dacl_protected=true, 2 ACEs, user+SYSTEM Full Control），
verifier 仍返回 `overall: FAIL`，属于误报。

**修复**：用 SDDL 字符串精确匹配 `S-1-5-18`。
**状态**：✅ 已修复
