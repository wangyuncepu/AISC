## 0. 核心原则

1. **所有命令必须可复制执行** — 从 PowerShell 终端直接粘贴。
2. **严禁记录任何 secret 或真实密钥** — 本测试只操作临时测试目录，不触及任何生产密钥文件。
3. **脚本/生产 verifier 不能作为唯一自证** — `icacls` 输出是独立于 Python 代码的外部证据。
4. **真实实机证据未回传前，不得宣称“Windows 验证完成”。**
5. **保持 stdlib-only** — 不要求 `gh`、`push`、CI、额外 pip 包。
6. **用户名可脱敏**（如替换为 `USERNAME` 或 `*`），但 **SID 语义必须保留**（如 `S-1-5-21-...` 部分可保留，否则无法判断 DACL 是否正确）。
7. **提交 hash 固定**，以便评审者对照代码版本。

## 6. 独立 PowerShell / icacls 检查 DACL（关键外部证据）

> **这是独立于 Python 代码的外部证据，是验证链中最重要的一环。**

### 6.1 定位 secret store 目录

```powershell
# 根据 verifier 输出或 JSON 报告找到 secrets 目录路径
# 通常为：$env:LOCALAPPDATA\aisc\secrets
$SECRETS_DIR = "$env:LOCALAPPDATA\aisc\secrets"

# 或从 JSON 报告中提取：
# $SECRETS_DIR = (Get-Content "$EVD\verify_s5_3_evidence.json" -Raw | ConvertFrom-Json).work_dir

Write-Host "Secrets directory: $SECRETS_DIR"
Test-Path $SECRETS_DIR   # 应返回 True
```

### 6.2 icacls 输出（DACL 完整视图）

```powershell
# 6.2.1 完整 DACL 输出（含继承信息）
icacls "$SECRETS_DIR" 2>&1 | Tee-Object -FilePath "$EVD\09-icacls-secrets-dir.txt"

# 6.2.2 保存为文件以便后续审查（带 /save 参数导出 SDDL）
icacls "$SECRETS_DIR" /save "$EVD\09-icacls-sddl.txt" 2>&1 | Out-Null
# 读取 SDDL（SDDL 是机器可读的标准格式）
Get-Content "$EVD\09-icacls-sddl.txt" | Tee-Object -FilePath "$EVD\09-icacls-sddl-readable.txt"
```

### 6.3 DACL 期望检查清单

逐项检查 `icacls` 输出，确认以下各项：

| 检查项 | 如何看 | 期望 | 实际（手工填写） |
|--------|--------|------|------------------|
| **DACL Protected（禁继承）** | `icacls` 输出若**不**含 `(I)` 标记（如 `NT AUTHORITY\SYSTEM:(I)(F)`），且无 inherited ACE | 无 `(I)` 标记的 ACE | ☐ |
| **当前用户 Full Control** | 第一行通常为 `<MACHINE>\<USER>:(F)` 或 `<USER>:(F)` | `(F)` 或 `(OI)(CI)(F)` | ☐ |
| **SYSTEM Full Control** | 含 `NT AUTHORITY\SYSTEM:(F)` | `(F)` 或 `(OI)(CI)(F)` | ☐ |
| **无 inherited ACE** | 所有 ACE 均不应带 `(I)` 前缀 | 零 inherited ACE | ☐ |
| **无 Everyone ALLOW** | 不应出现 `Everyone` | 无 | ☐ |
| **无 BUILTIN\Users ALLOW** | 不应出现 `BUILTIN\Users` 或 `Users` | 无 | ☐ |
| **无 Authenticated Users ALLOW** | 不应出现 `NT AUTHORITY\Authenticated Users` | 无 | ☐ |

> **注意**：`icacls` 的 `(F)` = Full Control，`(OI)` = Object Inherit（文件继承），`(CI)` = Container Inherit（子目录继承）。目录上 `(OI)(CI)(F)` 等效于 Full Control。
> 
> **不要**期待 `icacls` 输出与上述格式逐字相同——不同 Windows 版本/语言的输出格式略有差异（如中文系统可能显示 `NT AUTHORITY\SYSTEM:(F)` 或 `NT AUTHORITY\SYSTEM:(完全控制)`）。
> 关键是 **SID 语义一致**，不是文本外观。

### 6.4 使用 PowerShell Get-Acl 作为补充证据

```powershell
# 6.4.1 获取 ACL 对象
$acl = Get-Acl -Path "$SECRETS_DIR"

# 6.4.2 检查是否 protected（禁继承）
"AreAccessRulesProtected: $($acl.AreAccessRulesProtected)" | Tee-Object -FilePath "$EVD\09-ps-acl-summary.txt" -Append

# 6.4.3 列出所有 ACE（含 SID、权限、继承标志）
$acl.Access | Format-Table IdentityReference, FileSystemRights, AccessControlType, IsInherited, InheritanceFlags -AutoSize |
    Out-String -Width 200 | Tee-Object -FilePath "$EVD\09-ps-acl-aces.txt"

# 6.4.4 转换为 SDDL 格式（标准、可机器解析）
"SDDL: $($acl.Sddl)" | Tee-Object -FilePath "$EVD\09-ps-acl-sddl.txt"
```

## 7. Reparse Point / Junction 拒绝测试

> **目的**：验证 secret store 对 reparse point（junction / symbolic link）拒绝访问。

```powershell

New-Item -ItemType Directory -Path $FAKE_SECRETS -Force | Out-Null

# 7.4 尝试让 secure store 接受 junction（预期：失败）
$env:PYTHONPATH = "src"

from aisc.adapters.secret_store import ensure_secure_directory, SecureStorePermissionError

    ensure_secure_directory(Path(r'$JUNC_PARENT\secrets'))

    raise SystemExit(1)

    print(f'OK: secure store rejected junction: {type(e).__name__}: {e}')
    raise SystemExit(0)
"@ 2>&1 | Tee-Object -FilePath "$EVD\10-junction-test.txt"

Write-Host "Junction test exit code: $LASTEXITCODE"

```

**期望**：命令 exit code 为 0，且 `ensure_secure_directory` 抛出 `SecureStorePermissionError`。若 junction 被接受或创建了文件，测试失败。

## 11. 通过 / 失败判定

### 11.1 判定矩阵

| 检查项 | 通过条件 | 失败条件 |
|--------|----------|----------|
| unittest（聚焦） | S5.3/Windows real tests 全部 PASSED；其他平台专属 skip 有明确理由 | 任何 Windows real test FAILED/ERROR 或因非 Windows 被 skipped |

| icacls DACL protected | 无 `(I)` 标记的 ACE | 存在 inherited ACE |
| icacls 当前用户 | `(F)` 存在 | 不存在或权限不足 |
| icacls SYSTEM | `(F)` 存在 | 不存在或权限不足 |
| icacls 无 Everyone | 不出现 `Everyone` | 出现 `Everyone` ALLOW ACE |

| 篡改后 fail-closed | verifier exit code 非 `0` | verifier exit code 为 `0`（未检测到篡改） |
| 恢复后通过 | verifier exit code 恢复 `0` | 持续失败 |
| SDDL 一致 | `icacls /save` 的 SDDL 与 `Get-Acl` 的 SDDL 一致 | 不一致 |

### 11.2 判定结论

- **全部通过**：可声明“S5.3 Windows 实机验证完成”。
- **任一失败**：记录为 **`FAILED`**，在回传时注明失败项编号和终端输出/截图。不得声明“完成”。

## 13. 常见问题

### Q1: `icacls` 中文输出怎么看？
`icacls` 在中文 Windows 上会输出类似 `NT AUTHORITY\SYSTEM:(F)` 或 `NT AUTHORITY\SYSTEM:(完全控制)`。关键是 **SID 对应**而非文字。使用 `icacls /save` 导出 SDDL 可避免语言差异。

### Q2: 没有 `LOCALAPPDATA\aisc\secrets` 目录怎么办？
运行 `verify_s5_3_windows.py` 后该目录会自动创建。若未创建，检查：
- `%LOCALAPPDATA%` 环境变量是否正确设置
- 脚本是否有写权限
- 脚本 stdout/stderr 中的错误信息

### Q3: `mklink` 需要管理员权限？
Windows 10 Creators Update (1703) 后，开发人员模式下 `mklink` 不需要管理员权限。若未启用，在“设置 → 更新与安全 → 开发者选项”中开启“开发者模式”，或使用管理员终端。

### Q4: Home 版能完成验证吗？
Windows Home 版无 `secpol.msc` 等高级工具，但 `icacls` 和 `whoami /user` 仍可用。若 Home 版无法完成某项验证，在证据中如实标注，并附 OS SKU 信息。

### Q5: `TEST_USER` 应以什么身份运行？
以日常登录的普通 Windows 用户身份运行即可，不要求属于 `Administrators` 组。**不要使用 `SYSTEM` 帐户运行测试**——这会使验证失去意义（因为测试目标之一就是验证 SYSTEM 的独立 Full Control）。

## A. PowerShell 一键环境检查脚本

以下脚本可复制到 PowerShell 终端一次性检查前置环境：

```powershell
Write-Host "=== S5.3 Windows Environment Check ===" -ForegroundColor Cyan
Write-Host ""

Write-Host "[1/5] Python:" -ForegroundColor Yellow
try { python --version } catch { Write-Host "  FAIL: Python not found" -ForegroundColor Red }
Write-Host ""

Write-Host "[2/5] Git commit:" -ForegroundColor Yellow
try { git rev-parse HEAD } catch { Write-Host "  FAIL: git not found" -ForegroundColor Red }
Write-Host ""

Write-Host "[3/5] OS version:" -ForegroundColor Yellow
try { [System.Environment]::OSVersion.Version.ToString() } catch { Write-Host "  FAIL" -ForegroundColor Red }
Write-Host ""

Write-Host "[4/5] Current user SID:" -ForegroundColor Yellow
try { whoami /user } catch { Write-Host "  FAIL" -ForegroundColor Red }
Write-Host ""

try { fsutil fsinfo volumeinfo C: | Select-String "NTFS" } catch { Write-Host "  FAIL or not NTFS" -ForegroundColor Red }
Write-Host ""

Write-Host "=== Check complete ===" -ForegroundColor Cyan
```
